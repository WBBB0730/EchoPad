# macOS 应用菜单写死中文，应用的默认语言设成简体中文

电脑端的界面一律中文，但 macOS 顶部的应用菜单原来全是英文：没有自定义时 Tauri 装的是自带的默认菜单，文字是英文；安装包里没有任何语言目录，Info.plist 里的默认语言是 English，于是 macOS 往菜单里加的系统项（编辑菜单的自动填充、开始听写、表情与符号，窗口菜单的填充、居中、移动与调整大小、全屏幕拼贴、窗口列表）也显示英文。做法照 DevCube（它的 ADR-0019、ADR-0037），避开它踩过的坑。

应用菜单自己列出来：各项照 Tauri 默认菜单（`Menu::default`）的实际定义摆，用 Tauri 的系统菜单项保留原有的行为和快捷键，只把文字写死成中文，用词和 DevCube 一致。窗口和帮助两块用 Tauri 约定的 `WINDOW_SUBMENU_ID`、`HELP_SUBMENU_ID`：Tauri 凭它们把这两块登记成系统的窗口菜单和帮助菜单，漏掉的话 macOS 不会往里加窗口列表、平铺和帮助搜索。

macOS 加的系统项不归我们的文字管，它们的语言由系统在用户偏好的语言和应用支持的语言之间取交集决定。Tauri 的安装包不带语言目录，应用支持哪种语言就看 Info.plist 的 `CFBundleDevelopmentRegion`，所以在 `src-tauri/Info.plist` 里把它设成 `zh_CN`，打包时由 Tauri 合并进去。

代价：英文系统下菜单也是中文；网页视图的默认语言也跟着变成中文，界面本来就是中文，没有影响。Tauri 以后给默认菜单加项时不会自动跟进。将来要做多语言，需要撤掉这条，再按需列出支持的语言。

## Alternatives Considered

- 用 Tauri 的默认菜单：文字是英文，和界面对不上。
- 只把菜单文字换成中文、不改默认语言：系统加的项仍是英文，和中文混在一起。
- 运行时给应用写 `AppleLanguages` 偏好：等于替用户改系统设置里的应用语言，属于越权的做法。
