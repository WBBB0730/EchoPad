# Windows 安装包先不做代码签名

Windows 版电脑端（docs/prd/windows-desktop.md）的安装包不做代码签名就发布。没签名的安装包，用户第一次运行时 Windows 会弹出警告，要多点一步才能继续安装。

应用内更新不受影响：更新包是不是我们发的，靠的是 Tauri 更新签名（ADR-0009），和代码签名是两回事。以后加上代码签名，已经安装的用户照常更新，所以这个决定随时可以改。

先不签，是因为眼下没有一条走得通又划算的路（以下是 2026 年 11 月查到的情况）：

- 给开源项目免费签名的 SignPath Foundation 要求项目"已经以要签名的形式发布过"，所以无论如何都得先不签名发一版。它还要求用 OSI 认可的开源许可证，而仓库现在没有 LICENSE 文件。
- 微软的云签名 Artifact Signing 要求个人开发者在美国或加拿大，当作不可用。
- 向证书机构买证书要每年花钱，而且按 Tauri 文档的说法，新证书在攒够下载量之前，Windows 仍然可能弹出警告。花了钱也不能马上去掉警告。

发过带 Windows 安装包的版本之后，申请 SignPath Foundation 的签名，申请前先补上 LICENSE。它的其他要求：安装包上的发布者显示为 SignPath Foundation；安装包要能核实是从公开的源码构建出来的；每次发版的签名要人工批准；所有成员在 SignPath 和代码仓库上都开启多因素认证；项目主页上要有一段代码签名说明。申请下来以后更新这条 ADR 和发版流程（docs/prd/release.md）。

代价：在那之前，每个新用户第一次安装时都会看到警告，README 里要写明怎么继续安装。

## Alternatives Considered

- 买证书机构的证书：马上就能签，但每年要花钱，刚开始同样可能有警告。
- 微软的 Artifact Signing：由微软托管，不用自己保管密钥，但个人开发者只限美国和加拿大。
- 等申请到 SignPath Foundation 的签名再发 Windows 版：它要求先有发布过的版本，等不来。
