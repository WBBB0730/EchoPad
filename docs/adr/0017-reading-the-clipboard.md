# 读剪贴板：Android 靠前台服务和透明页面，电脑端看变化计数

剪贴板同步（docs/prd/clipboard-sync.md）要在两端读到用户刚复制的内容，Android 和 macOS 都不提供"剪贴板变了"的通用办法。做法都照用户最多的同类应用 KDE Connect。

**Android。** Android 10 起，只有拿着焦点的前台应用和默认输入法能读剪贴板；切到后台的应用不久还会被系统冻结，连接随之中断。手机端配过电脑时一直运行的前台服务（ADR-0019）让进程和连接在后台保持，电脑发来的内容随时可以写进手机剪贴板（只限制读，不限制写）。有电脑在线时，前台服务的常驻通知上有"发送剪贴板"按钮。剪贴板同步的两个开关（自动发送、接收）只管自动的部分，不影响用户主动同步。

手机到电脑的方向由用户触发：通知上的"发送剪贴板"按钮和下拉菜单里的磁贴打开一个透明的浮动页面，页面拿到焦点的那一刻读剪贴板、发出，然后关闭；前台服务没在运行时（例如被系统结束过），趁页面还看得见把它开起来，恢复后台同步，系统只允许看得见的页面启动前台服务。选中文字时走文字选择菜单和分享菜单，系统直接把文字交给 EchoPad，不用读剪贴板。回到 EchoPad 时也读一次，但只读进程启动后复制的内容。

**macOS。** 没有剪贴板变化的通知，所以每 0.5 秒看一次剪贴板的变化计数，变了才读取，剪贴板管理工具 Maccy 也是这么做的。看计数不读内容，开销很小。

**Windows。** 和 macOS 用同一套做法，计数是系统的剪贴板序列号，不用打开剪贴板就能读（docs/prd/windows-desktop.md）。Windows 没有限制应用读剪贴板的设置，不用提示用户授权。

代价：

- 点按钮时屏幕可能闪一下，Android 12 起系统还会提示"已粘贴"。
- 苹果从 macOS 15.4 起在预览一项剪贴板隐私保护：应用在用户没有操作时读剪贴板，系统会弹窗询问，用户也可以在系统设置里一律允许或一律拒绝。到 macOS 26 为止默认没有开启，以后的版本可能会开启。开启后，电脑端每次读剪贴板都可能弹窗，用户要在"隐私与安全性 › 粘贴"里允许 EchoPad；电脑端在被一律拒绝时提示用户去改。

## Alternatives Considered

- 只在 EchoPad 位于前台时读剪贴板：最简单，但手机到电脑这个方向每次都要切回 EchoPad，功能就没多大用处。
- 按需连接，不常驻：点按钮时再连电脑，没有常驻通知，也更省电。但每次要先找电脑、再握手，大约等一两秒，电脑到手机的方向在后台也收不到。
- 读系统日志发现剪贴板变化（KDE Connect 的可选做法）：要用户用 adb 授予 `READ_LOGS` 权限，普通用户做不到。
- 做成输入法或辅助功能服务：能在后台读剪贴板，但要用户换掉自己的输入法，或者交出能读取整个屏幕的权限，代价远大于收益。
- macOS 上监听系统事件代替轮询：系统没有公开的剪贴板变化事件。
- Windows 上用系统的剪贴板变化消息（`AddClipboardFormatListener`）代替轮询：要另开一个隐藏窗口和消息循环；和 macOS 共用每 0.5 秒看一次的做法更简单，看序列号的开销很小。
