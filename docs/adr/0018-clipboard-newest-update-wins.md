# 剪贴板同步按更新时间取舍，只同步连着时的复制

剪贴板同步（docs/prd/clipboard-sync.md）里，手机端只连电脑端，电脑端之间、手机端之间都靠转发：一部手机复制的内容经电脑端转给其他手机端，一台电脑复制的内容经手机端转给其他电脑端。转发不能变成无限循环，两台设备同时复制不同内容时也要停在同一条上。

每台设备只记一条：同步里最新的内容和它最后更新的时间。在本机复制时推送给连着的设备；设备之间只有一种剪贴板消息，带内容和更新时间，收到的设备只在它比自己的新时才用，用了就转给自己连着的其他设备，不发回给来源。每台设备都始终参与转发：关着"接收"的设备只是不写进自己的剪贴板，照样记下、照样转发，否则一部手机关了接收，两台电脑之间就断了。所以电脑端把剪贴板发给所有在线的手机端，不用知道各自的开关。先比较更新时间，相同再比较内容（按 UTF-8 字节），所以任意两条内容都分得出新旧。每台设备每用一次内容，它的更新时间都严格变新，而在途的内容是有限的，转发一定会停下，最后所有设备都停在最新的那条上。

更新时间是 Unix 毫秒。在本机复制时，更新时间取"现在"和"本机已知的最新更新时间加 1 毫秒"中较大的，这是混合逻辑时钟的做法：本机新复制的内容总比本机见过的任何内容都新，两台设备的时钟有几秒误差也不会让新复制的内容被当成旧的。

只同步连着时的复制，连上时不互报内容，断线期间的复制重连后不补发。断线期间，对方可能已经复制了新内容，而手机端看不到别的应用复制了什么（Android 不让后台应用读剪贴板）；不论断线是用户主动的（离开网络、退出电脑端）还是意外的（网络波动、被系统结束），重连时补发都可能把几小时前的旧内容补进来，或者盖掉对方新复制的内容。能确定没有争议的情况（例如断线期间手机一直锁屏、两端都没重启、网络没换）要多记好几样状态，而重连大多发生在手机亮屏之后，实际很少用得上。手机锁屏时连接保持（ADR-0019），最常见的"锁屏时电脑复制、拿起手机粘贴"不靠补发。

代价：断线期间的复制不会同步，要在重连后再复制一次。两台设备在几乎同一时刻复制不同内容时，以时钟较快那台的为准。

## Alternatives Considered

- 连上时双方互报内容和更新时间，较新的覆盖较旧的（KDE Connect 的做法）：断线期间的复制能补上，但出门回来、被系统结束过这些情况，可能补进旧内容，或者盖掉手机上 EchoPad 不知道的新复制。
- 只在意外断线、并且能确定对方没动过剪贴板时补发：没有争议，但要记录断线原因、两端是否重启、网络是否换过、手机是否亮过屏，实际很少能补上。
- 复制时推送的消息收到就用（KDE Connect 的做法）：设备两两直连时没问题，经转发时两条不同内容可能在设备之间一直来回覆盖。
- 每条内容带唯一编号，处理过的编号不再处理：能挡住同一条内容来回转发，但挡不住两条不同内容互相覆盖。
- 只用各自的墙上时钟：两台设备时钟有误差时，刚在本机复制的内容可能比刚收到的内容"旧"，被直接丢掉。
