# 连接全程 TLS 加密，配对码携带电脑端证书指纹

局域网连接原本不加密，手机端连上后先把设备密钥原样发过去。有了局域网查找以后，局域网里任何设备只要冒充电脑端标识广播自己的地址，就能骗到设备密钥，进而控制电脑；打的字和语音也以明文在局域网里传输。

所以电脑端第一次启动时生成一张长期使用的自签名证书（ECDSA P-256），私钥文件只有当前用户可以读写；连接改为 TLS 上的 WebSocket。配对码携带这张证书的 SHA-256 指纹，手机端扫码时记下，之后只连接证书指纹一致的电脑端，校验通过后才发送设备密钥。配对码本身就是一条线下可信的通道，所以从第一次连接起就锁定证书，不需要"首次连接时信任"。以前的配对没有证书指纹，升级后要重新扫码。

手机端继续用 Ktor 的 CIO 引擎，用它自带的 TLS 和自定义的证书校验；它只支持 TLS 1.2，所以两端使用 ECDHE + ECDSA 证书 + AES-GCM。电脑端用 rustls。

## Alternatives Considered

- Android 改用 OkHttp 引擎：可以用系统的 TLS 实现和 TLS 1.3，但 Android 和以后的 iOS 就不再共用同一套连接和心跳实现（ADR-0004）。CIO 的 TLS 1.2 配上证书锁定已经足够；如果它出现兼容问题再换。
- 只做双向验证，不加密：两端都证明自己知道设备密钥，能防止密钥被骗走，但打的字和语音仍是明文。
- 首次连接时信任对方证书：不用改配对码，但第一次连接如果恰好被冒充，就会一直信任错误的电脑。
