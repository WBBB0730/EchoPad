# 用未公开的手势事件模拟捏合缩放

缩放要和 Mac 触控板一样跟手、平滑、以指针为中心，但 macOS 没有任何公开接口能模拟触控板手势。电脑端因此发出带未公开字段的手势事件：事件类型 29，字段 110 设为 8（缩放），字段 132 是阶段（开始、进行中、结束），字段 113 是这一次的缩放量，再像其他模拟输入一样交给系统，由指针下的应用处理。用户最多的同类工具 Mac Mouse Fix 多年来一直用这四个字段做平滑缩放，WebKit 的测试工具也用同一组字段；在本机实测，应用能平滑缩放。

代价是苹果不保证这些字段一直有效：Mac Mouse Fix 模拟的另一种手势（切换桌面）就在 macOS 27 测试版里失效过。系统升级后缩放没反应时，先对照 Mac Mouse Fix 的改动。少数应用可能不响应模拟的缩放，例如 Chrome 系浏览器要累积一段缩放量才开始缩放。

## Alternatives Considered

- 发放大、缩小的快捷键（Command 加等号或减号）：公开、稳定，但一档一档地跳，不跟手，也不以指针为中心。
- 按住 Control 滚动：这是 Windows 上触控板缩放的通行做法，但 Mac 上很多应用不认，开了辅助功能里的缩放时还会放大整个屏幕。
- 虚拟一个触控板设备：需要苹果单独授予的驱动权限，macOS 也不把普通的 HID 触控板当成原生触控板。
