# 松开后整段整理，一次上屏

说话时，识别服务照常按停顿逐句给出定稿句，但电脑上不出字。松开说话按钮后，把这次语音输入的全部定稿句拼起来，交给整理服务整理一次，整理好一次上屏。这取代 ADR-0006 的边说边逐句整理。

逐句整理时，整理服务一次只能看到一句。识别服务按停顿切句：用户停下来想一想，一句话就被切成两段，半截话不带句尾标点；前一段已经上屏、不再修改，后一段里的改口（"不对，3 点"）就改不回去。整段整理一次看到全部内容，句子边界的标点、被切开的半句话、跨句改口都能处理。用合成语音实测的 12 个容易出错的用例里，整段整理全部处理正确，逐句整理遇到跨句改口全错。主流的同类产品（Wispr Flow、Typeless，开源的 VoiceInk、OpenWhispr、Handy）也是松开后整段整理、一次插入。

代价是松开后要等整段整理完，说得越长等得越久。实测火山方舟上的豆包 Seed 2.0 mini（5 次取中位）：34 字约 0.7 秒，158 字约 1.05 秒，448 字约 2.5 秒；识别服务在松开后收尾还要 0.2–0.6 秒。整理的快慢主要取决于模型：同样的整段，豆包 Seed 2.1 lite 要慢一倍左右，它光是返回第一个字就要 0.8–1.9 秒，用它逐句整理，松开后也要等约 1.5 秒。所以整理服务的预设只提供实测或按官方文档确认够快的模型（ADR-0007）。

整理结果一次上屏，不边生成边上屏：常见长度下，一次上屏只多等几百毫秒；边生成边上屏时，如果整理中途失败或超时，已经上屏的半段没法和识别原文衔接。整理失败或超时就上屏识别原文，并在手机端提示原因。

松开前电脑上什么都没有，所以用户可以上滑取消，整次丢弃，不用删任何已上屏的文字。说话时手机端也不显示识别中的文字：用户看着电脑说话，手机上只用说话按钮提示正在听。

## Alternatives Considered

- 逐句整理、立即上屏（ADR-0006）：松开后只需整理最后一句，但处理不了句子边界的标点和跨句改口。
- 留住最后一句：最后一个定稿句先不上屏，等下一句来了一起整理。松开后的等待和逐句整理差不多，但只能处理相邻两句之间的改口，实测仍有用例出错。
- 边说边上屏，之后用退格回改：上屏最快，但文字会闪；退格在自动补全、终端等应用里不可靠，用户中途动了插入点还会删错。系统输入法能在组字区里回改，EchoPad 用键盘事件上屏，做不到。
- 边生成边上屏：第一个字出来得更快，但整理中途失败时没法兜底，见上文。
