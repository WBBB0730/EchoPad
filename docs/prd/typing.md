# typing

**打字与按键**

## Problem Statement

只靠触控板和语音输入，还不能完全离开键盘：识别出的错字需要改；有些内容不方便说出口，比如网址、代码、密码；回车、退格、方向键、复制粘贴这类按键也离不开；看视频、听音乐时还要调播放和音量。打字时如果先在手机上打好再点发送，每次都多一步，也和在电脑键盘上打字的习惯不一样。

## Solution

点"键盘"弹出手机键盘，打字直接上屏：在手机键盘上选定的字立即输入到电脑的插入点，组字只显示在手机端；手机键盘上的退格、回车、空格直接作用于电脑。手机键盘上方有一排手机键盘没有的特殊键和一排快捷操作。点"媒体"展开一排媒体键。

## User Stories

1. 作为用户，我希望点"键盘"弹出手机键盘，用任意输入法（包括中文）打字，选定的字立刻出现在电脑的插入点。
2. 作为用户，我希望用拼音打字时，还没选定的拼音不会打进电脑，并且能在手机上看到正在拼的内容。
3. 作为用户，我希望手机键盘上的退格、回车、空格直接作用于电脑，就像在电脑键盘上按一样。
4. 作为用户，我希望按 Esc、Tab、删除、方向键、Home、End、上下翻页时，电脑立即收到对应的按键。
5. 作为用户，我希望一键完成复制、剪切、粘贴、撤销、重做、全选、切换应用，不用关心电脑是 Mac 还是 Windows。
6. 作为用户，我希望在手机上控制电脑的播放/暂停、上一首、下一首、音量加减和静音。
7. 作为用户，我希望打开键盘或媒体键时，触控区仍然可用。
8. 作为用户，我希望用系统返回手势收起手机键盘时，键盘面板也一起收起。

## Implementation Decisions

- 手机键盘直通：手机端不用普通文本框，而是用 Android 官方的输入法接口直接接收输入法的输出：
  - 输入法选定的字立即作为上屏文字发给电脑端，文字里的换行转成回车；
  - 组字只显示在手机端，不发送；组字过程中的退格由输入法自己处理；输入法结束组字但没有选字时，把组字按原样上屏，和普通文本框的行为一致；
  - 没有组字时的退格、删除、回车，转成对应的特殊键；
  - 手机端不保留已上屏的文字，输入法看到的编辑区始终是空的，因此不会回头改写已上屏的词，自动纠错只作用于正在组字的内容；
  - 关闭输入法的全屏模式，横屏时也能看到触控区。
- 键盘面板：手机键盘上方一排特殊键（Esc、Tab、删除、方向键、Home、End、上下翻页；退格、回车、空格用手机键盘自己的）和一排快捷操作，两排都可以左右滑动。
- 媒体键是特殊键的一种，用同一种消息；电脑端发送系统的媒体键事件，作用于正在播放的应用和系统音量。
- 键盘面板和媒体面板同一时间只展开一个；收起手机键盘时键盘面板一起收起。
- 快捷操作只描述意图，由电脑端按系统换成组合键：macOS 用 Command，重做是 Command+Shift+Z，切换应用是 Command+Tab；以后的 Windows 用 Ctrl。
- 未连接时按键不可用，打出的字不发送。
- 电脑端用 Unicode 键盘事件输入文字，与语音输入的上屏方式相同。
- iOS 版用 UIKit 的对应接口，第一版不做。

## Testing Decisions

- 电脑端集成测试：打字、特殊键（包括媒体键）、快捷操作的消息会变成对应的输入命令。
- 手机端单元测试：输入法的各种调用（选定文字、组字、结束组字、退格、删除、回车、带换行的文字）转成正确的消息序列，组字不发送。
- 联调时不在开发者自己的电脑上真实打字和按键，避免误操作；只验证手机端界面和消息收发。

## Out of Scope

- 先在手机上编辑再发送（ADR-0006）。
- 自定义快捷操作。
- 用语音指令编辑，例如"删掉上一句"。

## Further Notes

- 各家输入法在编辑区为空时处理退格的方式不同（有的发退格键，有的调用删除文字的接口），两种都要处理，并在主流输入法上实测。
- 待定：是否增加"撤回上一句"。
