# touchpad

**触控板**

## Problem Statement

用户不在键盘和鼠标旁边时，仍然想操作电脑，并且希望操作手感接近笔记本的触控板。

## Solution

手机端的触控区像笔记本触控板一样工作：单指滑动移动指针，轻点是左键单击，双指轻点是右键，双指滑动是滚动，轻点后按住再移动是拖拽。指针加速让慢移能精细定位、快移能跨过整个屏幕。系统级的触控板手势没法精确模拟，改用快捷键代替。

## User Stories

1. 作为用户，我希望单指在触控区滑动就能移动指针。
2. 作为用户，我希望慢慢移动时能精细定位，快速一划能跨过整个屏幕。
3. 作为用户，我希望轻点触控区就是左键单击。
4. 作为用户，我希望双指轻点就是右键。
5. 作为用户，我希望双指滑动就能滚动，并且滚动平滑、带惯性。
6. 作为用户，我希望轻点后按住再移动就能拖拽。
7. 作为用户，我希望点击时手机有震动反馈，这样能确认操作生效了。
8. 作为用户，我希望在触控区边缘操作时，不会误触发手机的系统手势。
9. 作为用户，我希望第一次在 Mac 上使用时，电脑端引导我开启需要的系统权限。

## Implementation Decisions

- 手机端只发送相对位移，并且每一帧屏幕刷新只合并发送一次。
- 指针加速在手机端计算，因为触摸时间戳在手机端最准；电脑端只负责应用位移，这样 Mac 和以后的 Windows 手感一致。
- 滚动惯性在手机端计算；电脑端用像素级滚动事件实现平滑滚动。
- 电脑端用 enigo 模拟键鼠，平滑滚动这类细节直接调用系统接口（ADR-0001）。
- 系统级触控板手势（三指切换桌面、捏合缩放、系统原生的惯性滚动）没有公开接口可以精确模拟，改用快捷键代替。
- 手势识别和指针加速放在手机端的共享代码里，Android 和 iOS 共用（ADR-0002）。
- Mac 需要"辅助功能"权限才能模拟键鼠；Windows 上，除非电脑端也以管理员身份运行，否则无法控制以管理员身份运行的窗口。
- Wi-Fi 丢包导致的偶发卡顿第一版先不处理；实测明显时，再为指针移动单独加 UDP 通道（ADR-0003）。

## Testing Decisions

- 只测外部行为：手势识别和指针加速用单元测试验证，给定一串触摸事件，检查产出的操作序列是否正确（移动、单击、右键、滚动、拖拽开始与结束）。
- 手感（加速曲线、滚动惯性）在真机上实测调参，不靠自动化测试。

## Out of Scope

- 精确模拟系统级触控板手势。
- 用手机键盘打字输入到电脑。
- Windows 版和 iOS 版（架构已支持，第一版只做 Mac 和 Android）。

## Further Notes

- 待定：三指等系统手势具体映射到哪些快捷键。
- 屏幕边缘的系统手势（Android 的侧边返回，iOS 的底部回到主屏和顶部下拉）会和触控区冲突，触控区要避开屏幕边缘。iOS 只能把这些系统手势改成要滑两次才触发，不能完全关闭。
