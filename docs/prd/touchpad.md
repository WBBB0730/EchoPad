# touchpad

**触控板**

## Problem Statement

用户不在键盘和鼠标旁边时，仍然想操作电脑，并且希望操作手感接近笔记本的触控板。

## Solution

手机端的触控区像笔记本触控板一样工作：单指滑动移动指针，轻点立即左键单击，连续两次轻点是双击，双指轻点是右键，双指滑动是滚动，按住不动一会儿再移动是拖拽。指针加速让慢移能精细定位、快移能跨过整个屏幕，指针速度和滚动速度可以自己调。竖屏、横屏都能用。

## User Stories

1. 作为用户，我希望单指在触控区滑动就能移动指针。
2. 作为用户，我希望慢慢移动时能精细定位，快速一划能跨过整个屏幕。
3. 作为用户，我希望轻点触控区就是左键单击，抬手立即生效、没有延迟；连续两次轻点就是双击。
4. 作为用户，我希望双指轻点就是右键。
5. 作为用户，我希望双指滑动就能滚动，并且滚动平滑、带惯性。
6. 作为用户，我希望按住不动一会儿再移动就能拖拽，并且能感觉到什么时候可以开始拖。
7. 作为用户，我希望点击时手机有震动反馈，这样能确认操作生效了。
8. 作为用户，我希望在触控区边缘操作时，不会误触发手机的系统手势。
9. 作为用户，我希望使用时手机屏幕不会自动熄灭。
10. 作为用户，我希望第一次在 Mac 上使用时，电脑端请求需要的系统权限，并显示是否已授权。
11. 作为用户，我希望缺少权限时能一键打开对应的系统设置，授权后电脑端自己更新状态，不用重启或刷新。
12. 作为用户，我希望调整指针速度和滚动速度，并且下次打开时还记得。
13. 作为用户，我希望横着拿手机时触控区更宽，按钮放在侧边，不挤占触控区的高度。
14. 作为用户，我希望转动手机时连接不断，展开的面板保持不变。

## Implementation Decisions

- 手势识别、指针加速和滚动惯性都在手机端的共享代码里，Android 和 iOS 共用（ADR-0002）。
- 轻点：移动不超过 8dp 就抬起，抬手立即发出单击，不等待。连续两次轻点发出两次单击，由电脑按系统的双击间隔识别成双击。
- 拖拽：按下后 250ms 内没有移动超过 8dp，就按下左键并震动提示，之后移动是拖拽，抬手松开左键。250ms 内开始移动，就只移动指针。
- 双指在 300ms 内抬起且没有滑动，是右键。三指及以上的手势第一版不处理。
- 超出轻点范围之前的轻微抖动不移动指针。
- 指针加速在手机端计算，因为触摸时间戳在手机端最准：慢速时按 1.2 倍、快速时按 4.5 倍换算，中间平滑过渡。电脑端只负责应用位移，这样 Mac 和以后的 Windows 手感一致。
- 指针速度和滚动速度在手机端设置，范围 0.5–2 倍，默认 1 倍，保存在手机端。指针速度乘在指针加速的结果上；滚动速度同时作用于滚动惯性。
- 手机端只发送相对位移，每一帧屏幕刷新合并发送一次；按键操作立即发送，并先发出之前累积的移动。
- 滚动：手机上滑动 1dp 对应电脑上滚动 2 像素，内容跟随手指移动。双指快速滑动后离开，按惯性逐渐减速，再次按下立即停止。
- 电脑端用 enigo 模拟键鼠，滚动使用像素级的平滑滚动（ADR-0001）。不足一个像素或一个点的位移会累积起来，不会被取整丢掉。
- Mac 需要"辅助功能"权限：电脑端第一次尝试时弹出系统授权提示；未授权期间每秒检查一次，不必等手机端发来操作，授权后无需重启，界面状态自动更新。未授权时状态行提供"打开系统设置"，直接打开辅助功能的设置页。Windows 上，除非电脑端也以管理员身份运行，否则无法控制以管理员身份运行的窗口。
- 触控区避开屏幕左右两侧的系统手势区域；手机端打开时保持屏幕常亮。
- 横屏时触控区占满左侧全部高度，按钮放在右侧一列（DESIGN.md）。连接由界面之外的部分持有，转屏时不断开；展开的面板在转屏后保持；按住说话时转屏会结束这次语音输入。
- Wi-Fi 丢包导致的偶发卡顿第一版先不处理；实测明显时，再为指针移动单独加 UDP 通道（ADR-0003）。

## Testing Decisions

- 只测外部行为：手势识别用单元测试验证，给定一串触摸事件，检查产出的操作序列是否正确（移动、单击、连续单击、右键、滚动与惯性、按住开始拖拽与结束、三指忽略）。
- 指针加速、滚动惯性、按帧合并发送分别用单元测试验证。
- 电脑端用集成测试验证指针与按键消息会转成对应的输入命令。
- 手感（加速曲线、滚动惯性、各项时间阈值）在真机上实测调参，不靠自动化测试。

## Out of Scope

- 精确模拟系统级触控板手势。
- Windows 版和 iOS 版（架构已支持，第一版只做 Mac 和 Android）。

## Further Notes

- 待定：三指等系统手势是否要映射成快捷键，以及具体映射到哪些。
- 拖拽不用"轻点后按住再移动"：那样每次单击都要等一段时间确认不是拖拽，电脑的触控板开启双击拖移时也有同样的延迟；而如果单击立即发出，紧接着的按下会被电脑当成双击后拖动，在文字里按词选中、在访达里可能打开文件。按住后拖动和 UU 远程的鼠标指针模式一致。
- 250ms 是初始值，按住的时间太短容易误触发拖拽，太长拖拽起来慢，要在真机上实测调整。
- 屏幕边缘的系统手势（Android 的侧边返回，iOS 的底部回到主屏和顶部下拉）会和触控区冲突。iOS 只能把这些系统手势改成要滑两次才触发，不能完全关闭。
