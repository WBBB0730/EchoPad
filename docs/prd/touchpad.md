# touchpad

**触控板**

## Problem Statement

用户不在键盘和鼠标旁边时，仍然想操作电脑，并且希望操作手感接近笔记本的触控板。

## Solution

手机端的触控区像笔记本触控板一样工作：单指滑动移动指针，轻点立即左键单击，连续两次轻点是双击，双指轻点是右键，双指滑动是滚动，双指张开或捏合是缩放，按住不动一会儿再移动是拖拽。触控区最右侧有一条滚动条，单手拿手机时大拇指在上面上下滑就能滚动。指针加速让慢移能精细定位、快移能跨过整个屏幕，指针速度、滚动速度，以及双指滚动和滚动条各自的滚动方向都可以自己调。竖屏、横屏都能用。

## User Stories

1. 作为用户，我希望单指在触控区滑动就能移动指针。
2. 作为用户，我希望慢慢移动时能精细定位，快速一划能跨过整个屏幕。
3. 作为用户，我希望轻点触控区就是左键单击，抬手立即生效、没有延迟；连续两次轻点就是双击。
4. 作为用户，我希望双指轻点就是右键。
5. 作为用户，我希望双指滑动就能滚动，并且滚动平滑、带惯性。
6. 作为用户，我希望按住不动一会儿再移动就能拖拽，并且能感觉到什么时候可以开始拖。
7. 作为用户，我希望点击时手机有震动反馈，这样能确认操作生效了。
8. 作为用户，我希望在触控区边缘操作时，不会误触发手机的系统手势。
9. 作为用户，我希望使用时手机屏幕不会自动熄灭。
10. 作为用户，我希望第一次在 Mac 上使用时，电脑端请求需要的系统权限，并显示是否已授权。
11. 作为用户，我希望缺少权限时能一键打开对应的系统设置，授权后电脑端自己更新状态，不用重启或刷新。
12. 作为用户，我希望调整指针速度和滚动速度，并且下次打开时还记得。
13. 作为用户，我希望横着拿手机时触控区更宽，按钮放在侧边，不挤占触控区的高度。
14. 作为用户，我希望转动手机时连接不断，手机键盘是否打开、常驻按键选中了哪一组都保持不变。
15. 作为用户，我希望把指针推到屏幕边缘后，往回滑时指针马上跟着往回走。
16. 作为用户，我希望双指张开或捏合就能像在触控板上一样平滑地缩放网页、图片和地图，捏回原来的距离就回到原来的大小。
17. 作为用户，我希望双指滚动时不会因为手指距离变了一点就变成缩放。
18. 作为用户，我希望单手拿手机时，用大拇指在滚动条上上下滑就能滚动，换算、速度和惯性和双指滚动一样。
19. 作为用户，我希望移动指针时手指滑进滚动条，指针照常移动，不会突然变成滚动。
20. 作为用户，我希望想移动指针时手指正好按在滚动条上、横着滑出去，指针也照常移动。
21. 作为用户，我希望单手时大拇指贴着屏幕右边缘竖着滑也能滚动。
22. 作为用户，我希望双指滚动和滚动条的方向可以各自在自然和传统之间选，和我在电脑上的习惯一致，并且下次打开时还记得。

## Implementation Decisions

- 手势识别、指针加速和滚动惯性都在手机端的共享代码里，Android 和 iOS 共用（ADR-0002）。
- 轻点：移动不超过 8dp 就抬起，抬手立即发出单击，不等待。连续两次轻点发出两次单击，由电脑按系统的双击间隔识别成双击。
- 拖拽：按下后 250ms 内没有移动超过 8dp，就按下左键并震动提示，之后移动是拖拽，抬手松开左键。250ms 内开始移动，就只移动指针。
- 双指在 300ms 内抬起且没有滑动或缩放，是右键。三指及以上的手势第一版不处理。
- 双指滚动还是缩放，参照 Mac 触控板和 libinput：两根手指都移动超过 8dp 后，朝大致相同的方向（夹角小于 90°）是滚动，朝相反的方向是缩放；只有一根手指在动、移动超过 24dp（约 4mm）时也是滚动。判定后到手指离开都不变。双指滚动时总有一根手指先动，只看两指距离的变化会把它误判成缩放；所以和 Mac 一样，只动一根手指不能开始缩放，缩放开始后才允许一根手指停住。同一次触摸事件里移动的手指一起识别，否则只更新了一根手指时，两指的距离会暂时变化。
- 缩放：缩放量是两指距离相对上一次的倍数，每帧合并（相乘）发送一次；开始和结束立即发送。捏回原来的距离，倍数乘起来正好回到原大小。缩放进行中又按下第三根手指，这次缩放就结束。
- 电脑端把缩放发成和触控板一样的原生捏合手势，交给指针下的应用，用的是 macOS 未公开的手势事件字段（ADR-0012）。缩放进行中断线时，电脑端补发结束。Windows 版再做。
- 超出轻点范围之前的轻微抖动不移动指针。
- 指针加速在手机端计算，因为触摸时间戳在手机端最准：慢速时按 1.2 倍、快速时按 4.5 倍换算，中间平滑过渡。电脑端只负责应用位移，这样 Mac 和以后的 Windows 手感一致。
- 指针速度和滚动速度在手机端设置，范围 0.5–2 倍，默认 1 倍，保存在手机端。指针速度乘在指针加速的结果上；滚动速度同时作用于滚动惯性。
- 手机端只发送相对位移，有累积的移动时在下一帧屏幕刷新时合并发送一次，手指不动时不占用屏幕刷新；按键操作立即发送，并先发出之前累积的移动。
- 滚动：手机上滑动 1dp 对应电脑上滚动 2 像素。双指快速滑动后离开，按惯性逐渐减速，再次按下立即停止。
- 滚动方向：双指滚动和滚动条各自在手机端选自然或传统，保存在手机端，上下左右一起反过来，惯性也跟着同一个方向。自然是内容跟着手指走；传统和拖电脑上的滚动条一样，手指往下页面往下翻。两者默认都是自然，和 Mac 的默认一致，交给用户自己选；分开设置和 Synaptics 一样。设置里滚动条这一行叫"单指滚动"。
- 滚动方向放在手机端选，不跟随电脑的系统设置：模拟出来的滚动不受 Mac 系统滚动方向设置的影响（Deskflow 的 Mac 客户端也一样，最后靠自己加反向选项解决），想跟随就要读 Mac 没公开文档的设置项；Windows 的触控板和鼠标方向又是分开设置的，台式机可能没有触控板设置。放在手机端，连哪台电脑都一样。
- 滚动条：参照 Remote Mouse、WiFi Mouse 等同类应用和笔记本触控板的边缘滚动，放在触控区最右侧，大拇指够得着。在滚动条上按下的那根手指移动超过 8dp 时按方向判定：上下方向为主是滚动，之后的换算、滚动速度和惯性都和双指滚动一样，只滚上下，左右滚动仍用双指，方向见上一条；左右方向为主是移动指针，和触控区单指移动一样有指针加速，但不会变成单击或拖拽，因为这多半是想移动指针时正好按到了滚动条。参照 libinput 的边缘滚动：手指在边缘区按下、还没锁定成滚动就移出边缘区，这次触摸按普通的指针移动处理。判定后到手指离开都不变，滑出滚动条也一样。在触控区按下，滑进滚动条也照常移动指针。滚动条上轻点不做任何事，其他手指不参与。竖屏时滚动条的触摸范围向右延伸到屏幕边缘（外观不变），贴着屏幕边缘竖着滑也能滚动：Android 的边缘返回手势在手指先竖着移动时会放弃、把触摸留给应用，先横着移动时才接管成返回，所以两者不冲突；横屏时滚动条右边是按钮列，不延伸。
- 电脑端用 enigo 模拟键鼠，滚动使用像素级的平滑滚动（ADR-0001）。不足一个像素或一个点的位移会累积起来，不会被取整丢掉。
- 每次移动指针都读取系统当前的指针位置，接上或拔掉显示器、改分辨率、远程桌面软件增减虚拟显示器之后照常工作。enigo 0.6.1 会一直用启动时的主显示器换算位置，上游已修复但尚未发版，暂时固定到包含修复的提交，发版后换回正式版。
- 指针推到屏幕边缘时停在边上。Mac 不会替模拟的移动挡住屏幕边缘，移到屏幕外的位置会被系统原样记下，往回移动时要先走完超出的距离；所以电脑端每次移动前自己把目标限制在显示器上：落在任意一块显示器上就照常移动，否则沿着当前显示器的边移动；指针已在所有显示器之外时（比如刚拔掉显示器），先拉回最近的一块。Windows 自己会挡住，不需要处理。
- Mac 需要"辅助功能"权限：电脑端第一次尝试时弹出系统授权提示；之后每秒检查一次，不必等手机端发来操作：授权后无需重启，使用中被关掉时状态也立即更新，界面状态始终和实际一致。未授权时状态行提供"打开系统设置"，直接打开辅助功能的设置页。Windows 上，除非电脑端也以管理员身份运行，否则无法控制以管理员身份运行的窗口。
- 触控区避开屏幕左右两侧的系统手势区域；手机端打开时保持屏幕常亮。
- 横屏时触控区占满左侧全部高度，按钮放在右侧一列（DESIGN.md）。连接由界面之外的部分持有，转屏时不断开；手机键盘是否打开、常驻按键选中了哪一组在转屏后保持；按住说话时转屏会结束这次语音输入。
- Wi-Fi 丢包导致的偶发卡顿第一版先不处理；实测明显时，再为指针移动单独加 UDP 通道（ADR-0003）。

## Testing Decisions

- 只测外部行为：手势识别用单元测试验证，给定一串触摸事件，检查产出的操作序列是否正确（移动、单击、连续单击、右键、滚动与惯性及其两个方向、按住开始拖拽与结束、缩放的判定与结束、三指忽略）。滚动条同样用单元测试验证：超出轻点范围才判定、上下为主时只滚上下、自然和传统两个方向、快速滑动后离开产生惯性、左右为主时移动指针且不产生惯性、轻点什么都不发。
- 指针加速、滚动惯性、按帧合并发送分别用单元测试验证。
- 屏幕边缘的限制用单元测试验证：跨到相邻显示器、在边缘停住、沿边滑动、两块显示器边缘不对齐处、指针在所有显示器之外。
- 电脑端用集成测试验证指针、按键和缩放消息会转成对应的输入命令。发给系统的原生手势事件不做自动化测试，在真机上验证。
- 手感（加速曲线、滚动惯性、各项时间阈值）在真机上实测调参，不靠自动化测试。

## Out of Scope

- 精确模拟系统级触控板手势。
- Windows 版和 iOS 版（架构已支持，第一版只做 Mac 和 Android）。

## Further Notes

- 待定：三指等系统手势是否要映射成快捷键，以及具体映射到哪些。
- 拖拽不用"轻点后按住再移动"：那样每次单击都要等一段时间确认不是拖拽，电脑的触控板开启双击拖移时也有同样的延迟；而如果单击立即发出，紧接着的按下会被电脑当成双击后拖动，在文字里按词选中、在访达里可能打开文件。按住后拖动和 UU 远程的鼠标指针模式一致。
- 滚动条延伸到屏幕边缘后，要在真机上确认单手握持时手掌碰到右边缘会不会误滚动，以及手机系统自带的边缘防误触会不会过滤掉贴边的触摸。
- 滚动条的方向，用户的预期分两派：看它像滚动条的，期望往下滑页面往下翻；把它当成单指版双指滚动的，期望和双指同向。同类产品里两种都有，Synaptics 的边缘滚动和双指滚动可以各自调方向，libinput 两者共用一个开关。Synaptics 触控板的边缘滚动和手机自带的快速滚动条都是传统方向，滚动条看起来也更像滚动条，实测容易按滚动条的方向去拖；但哪一派都不占绝对多数，所以默认和双指滚动一样是自然，两个方向都让用户自己选。
- 滚动条上判定方向用 45°（左右位移大于上下位移就是移动指针），大拇指上下滑时会带一点弧度，实测容易误判时再调。
- 250ms 是初始值，按住的时间太短容易误触发拖拽，太长拖拽起来慢，要在真机上实测调整。
- 缩放先按两指距离一比一换算，缩放快慢在真机上实测调整。Chrome 系浏览器要累积一段缩放量才开始缩放，实测明显时再处理。
- 屏幕边缘的系统手势（Android 的侧边返回，iOS 的底部回到主屏和顶部下拉）会和触控区冲突。iOS 只能把这些系统手势改成要滑两次才触发，不能完全关闭。
