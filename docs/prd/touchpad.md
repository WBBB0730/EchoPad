# touchpad

**触控板**

## Problem Statement

用户不在键盘和鼠标旁边时，仍然想操作电脑，并且希望操作手感接近笔记本的触控板。

## Solution

手机端的触控区像笔记本触控板一样工作：单指滑动移动指针，轻点是左键单击，连续两次轻点是双击，双指轻点是右键，双指滑动是滚动，轻点后按住再移动是拖拽。指针加速让慢移能精细定位、快移能跨过整个屏幕。

## User Stories

1. 作为用户，我希望单指在触控区滑动就能移动指针。
2. 作为用户，我希望慢慢移动时能精细定位，快速一划能跨过整个屏幕。
3. 作为用户，我希望轻点触控区就是左键单击，连续两次轻点就是双击。
4. 作为用户，我希望双指轻点就是右键。
5. 作为用户，我希望双指滑动就能滚动，并且滚动平滑、带惯性。
6. 作为用户，我希望轻点后按住再移动就能拖拽。
7. 作为用户，我希望点击时手机有震动反馈，这样能确认操作生效了。
8. 作为用户，我希望在触控区边缘操作时，不会误触发手机的系统手势。
9. 作为用户，我希望使用时手机屏幕不会自动熄灭。
10. 作为用户，我希望第一次在 Mac 上使用时，电脑端请求需要的系统权限，并显示是否已授权。

## Implementation Decisions

- 手势识别、指针加速和滚动惯性都在手机端的共享代码里，Android 和 iOS 共用（ADR-0002）。
- 轻点：移动不超过 8dp，并在 220ms 内抬起。轻点后 220ms 内再次按下，抬起是双击，移动则是拖拽；所以单击要等这 220ms 过去才发出。双指在 300ms 内抬起且没有滑动，是右键。三指及以上的手势第一版不处理。
- 超出轻点范围之前的轻微抖动不移动指针。
- 指针加速在手机端计算，因为触摸时间戳在手机端最准：慢速时按 1.2 倍、快速时按 4.5 倍换算，中间平滑过渡。电脑端只负责应用位移，这样 Mac 和以后的 Windows 手感一致。
- 手机端只发送相对位移，每一帧屏幕刷新合并发送一次；按键操作立即发送，并先发出之前累积的移动。
- 滚动：手机上滑动 1dp 对应电脑上滚动 2 像素，内容跟随手指移动。双指快速滑动后离开，按惯性逐渐减速，再次按下立即停止。
- 电脑端用 enigo 模拟键鼠，滚动使用像素级的平滑滚动（ADR-0001）。不足一个像素或一个点的位移会累积起来，不会被取整丢掉。
- Mac 需要"辅助功能"权限：电脑端第一次尝试时弹出系统授权提示，之后每秒检查一次，授权后无需重启，界面显示授权状态。Windows 上，除非电脑端也以管理员身份运行，否则无法控制以管理员身份运行的窗口。
- 触控区避开屏幕左右两侧的系统手势区域；手机端打开时保持屏幕常亮。
- Wi-Fi 丢包导致的偶发卡顿第一版先不处理；实测明显时，再为指针移动单独加 UDP 通道（ADR-0003）。

## Testing Decisions

- 只测外部行为：手势识别用单元测试验证，给定一串触摸事件，检查产出的操作序列是否正确（移动、单击、双击、右键、滚动与惯性、拖拽开始与结束、三指忽略）。
- 指针加速、滚动惯性、按帧合并发送分别用单元测试验证。
- 电脑端用集成测试验证指针与按键消息会转成对应的输入命令。
- 手感（加速曲线、滚动惯性、各项时间阈值）在真机上实测调参，不靠自动化测试。

## Out of Scope

- 精确模拟系统级触控板手势。
- 用手机键盘打字输入到电脑。
- Windows 版和 iOS 版（架构已支持，第一版只做 Mac 和 Android）。

## Further Notes

- 待定：三指等系统手势是否要映射成快捷键，以及具体映射到哪些。
- 屏幕边缘的系统手势（Android 的侧边返回，iOS 的底部回到主屏和顶部下拉）会和触控区冲突。iOS 只能把这些系统手势改成要滑两次才触发，不能完全关闭。
