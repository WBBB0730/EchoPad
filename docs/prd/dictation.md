# dictation

**语音输入**

## Problem Statement

在电脑上打字慢。用户想用说话代替打字，并且要求识别尽可能准、说完马上出字，而且输入的文字是整理过的。现有的语音输入产品很难同时做到：边说边出字的产品基本照原话转写，口头禅和重复都会留下；整理得好的产品，说完要等 2–3 秒。

## Solution

按住手机端的说话按钮开始说话。识别过程中，临时文字显示在手机端。识别服务每给出一个定稿句，就立刻整理，并上屏到电脑的插入点。松开按钮后，只需要等最后一句整理完。

## User Stories

1. 作为用户，我希望按住说话按钮就开始语音输入，松开就结束。
2. 作为用户，我希望说话时能在手机端看到临时文字，这样知道识别是否正常。
3. 作为用户，我希望只有整理好的文字才上屏，临时文字不会打进电脑。
4. 作为用户，我希望口头禅和重复自动去掉，标点也正确。
5. 作为用户，我希望句内改口时只保留我最后的说法。
6. 作为用户，我希望松开按钮后，最后一句几乎马上就上屏。
7. 作为用户，我希望当前窗口里出现的专有名词能被正确识别。
8. 作为用户，我希望上屏文字出现在电脑当前的插入点，中文能正常输入。
9. 作为用户，我希望在部分终端、远程桌面、游戏这类应用里也能正常上屏。
10. 作为用户，我希望说到一半断线时，未完成的内容不会上屏。

## Implementation Decisions

- 手机端按住说话期间录制 16kHz 单声道音频，实时发给电脑端（ADR-0005）。
- 电脑端调用豆包流式语音识别，并附带屏幕参考；识别服务的密钥只存在电脑端（ADR-0005）。
- 临时文字回传给手机端显示，不上屏。
- 每个定稿句立即交给一个响应快的小模型整理，整理完立即上屏，上屏后不再修改（ADR-0006）。
- 上屏方式：默认用 Unicode 键盘事件直接输入。少数应用不接受这种输入，改用"写入剪贴板 + 模拟粘贴"。
- 如果豆包在流式识别时支持自带的去语气词，就同时开启，减轻整理的负担（尚未核实）。

## Testing Decisions

- 只测外部行为：用假的识别服务（按顺序返回预设的临时文字和定稿句）测试整个流程。要验证：临时文字不上屏；定稿句按顺序整理后上屏；断线时未完成的内容被丢弃。
- 识别准确率和延迟用用户自己的真实语音实测，不放进自动化测试。

## Out of Scope

- 跨句改口。
- 本地识别模型（保留为以后的选项，见 ADR-0005）。
- 按当前应用调整语气、从用户的修改中自动学习词汇、选中文字后用语音指挥改写。
- 说完后整段重写。
