# dictation

**语音输入**

## Problem Statement

在电脑上打字慢。用户想用说话代替打字，并且要求识别尽可能准、说完马上出字，而且输入的文字是整理过的。现有的语音输入产品很难同时做到：边说边出字的产品基本照原话转写，口头禅和重复都会留下；整理得好的产品，说完要等 2–3 秒。

## Solution

按住手机端的说话按钮开始说话，松开结束。说话时识别服务按停顿一句一句识别，电脑上不出字；松开后，这次说的全部内容一起整理，整理好一次上屏到电脑的插入点（ADR-0013）。说到一半想重来，手指上滑再松开，就取消这次语音输入。说错的字用手机键盘上的退格修改（docs/prd/typing.md）。

EchoPad 不内置任何密钥（ADR-0007）。用户在电脑端的设置里选择识别服务和整理服务，填写自己的密钥；整理服务可以关闭。

## User Stories

1. 作为用户，我希望按住说话按钮就开始语音输入，松开就结束。
2. 作为用户，我希望说到一半想重来时，手指上滑再松开就能取消，电脑上什么都不输入。
3. 作为用户，我希望只有整理好的文字才上屏。
4. 作为用户，我希望口头禅和重复自动去掉，标点也正确，包括我说话中途停顿的地方。
5. 作为用户，我希望改口时只保留我最后的说法，不管改口是在同一句里，还是隔了几句。
6. 作为用户，我希望松开按钮后，整理好的文字很快上屏。
7. 作为用户，我希望当前窗口里出现的专有名词能被正确识别。
8. 作为用户，我希望上屏文字出现在电脑当前的插入点，中文能正常输入。
9. 作为用户，我希望说到一半断线时，这次说的内容不会上屏。
10. 作为用户，我希望电脑端没配置好或识别出错时，手机端能告诉我。
11. 作为用户，我希望整理失败时，识别原文照样上屏，手机端告诉我整理失败的原因。
12. 作为用户，我希望在电脑端的设置里选择识别服务，填写自己的密钥。
13. 作为用户，我希望从几家预设的整理服务和它们提供的模型中选择，不用自己填模型名；也能填自己的服务地址和模型。
14. 作为用户，我希望不想付整理的费用时可以关闭整理，识别结果原样上屏。
15. 作为用户，我希望在设置里看到已保存的密钥，方便核对和复制，同时密钥默认遮住，不被旁人看到。

## Implementation Decisions

- 手机端按住说话期间录制 16kHz、16 位、单声道音频，每 100ms 发一段给电脑端（ADR-0005）。
- 识别服务（ADR-0005）：
  - 豆包流式语音识别（默认）：双向流式（优化版）接口，资源可选 2.0 或 1.0 的小时版、并发版，默认 2.0 小时版。开启二遍识别（每句话停顿约 0.8 秒后判定说完，用更准的非流式模型重新识别，结果才标记为定稿句）和语义顺滑（识别时就去掉语气词和重复）。附带屏幕参考。
  - 阿里百炼 Fun-ASR 实时识别：模型 `fun-asr-realtime`，句子停顿 0.8 秒判定说完；第一版不附带屏幕参考。
- 屏幕参考第一版只附带当前应用和窗口的名称，作为文字上下文。读取窗口标题用的是辅助功能权限，模拟键鼠本来就需要这个权限。
- 识别中的文字不发给手机端。说话时手机端只用说话按钮提示正在听（DESIGN.md）。
- 松开说话按钮后，把这次语音输入的全部定稿句按顺序拼起来（英文句子之间补一个空格），交给整理服务整理一次，整理好一次上屏，上屏后不再修改（ADR-0013）：
  - 整理服务的预设和可选的模型（第一个是默认）：
    - 火山方舟：豆包 Seed 2.0 mini（`doubao-seed-2-0-mini-260428`）、DeepSeek V4.1 Flash（`deepseek-v4-1-flash-261017`）；
    - 阿里百炼：Qwen3.8 Flash（`qwen3.8-flash`）、Qwen3.7 Flash（`qwen3.7-flash`）；
    - DeepSeek：DeepSeek V4.1 Flash（`deepseek-flash`）；
    - OpenAI：GPT-6 Luna（`gpt-6-luna`）、GPT-5.4 mini（`gpt-5.4-mini`）；
    - OpenRouter：GPT-6 Luna（`openai/gpt-6-luna`）、Gemini 3.1 Flash Lite（`google/gemini-3.1-flash-lite`）、Qwen3.8 Flash（`qwen/qwen3.8-flash`）；
    - 自定义地址：用户填写地址和模型。
  - 预设的模型只能从列表里选，请求时都关闭深度思考，各家的写法随预设内置（ADR-0007）。自定义地址不附加这类参数。
  - 设置里保存的模型不在所选预设的列表里时（例如旧版本的默认模型），改用这个预设的默认模型；已经去掉的预设（本机 Ollama）改用火山方舟。
  - 整理失败或超过 8 秒时，上屏识别原文，不丢掉用户说的话，并在手机端提示整理失败的原因。
  - 整段都是口头禅时，整理结果为空，不上屏。
  - 整理关闭时，定稿句原样上屏。
- 取消：说话时手指从说话按钮往上滑到按钮上边缘以外，按钮变成"松开取消"；这时松手，手机端停止录音并通知电脑端，电脑端停止识别、丢弃这次语音输入的全部内容，什么都不上屏。手指滑回按钮上则恢复，松手后照常上屏。
- 上屏用 Unicode 键盘事件直接输入。
- 设置（ADR-0007）：
  - 服务选择、模型、开关和密钥都保存在电脑端的设置文件里，文件只有当前用户可以读写；设置界面显示已保存的密钥，默认遮住，可以点开查看；清空输入框再保存即删除密钥；
  - 同一家服务商的密钥只填一次，例如识别和整理都选阿里百炼时共用一个密钥；
  - 保存后立即生效，不用重启电脑端；
  - 识别服务没有密钥，或整理开启但没配置好时，语音输入不可用，界面和手机端都会提示。

## Testing Decisions

- 只测外部行为：用假的识别服务（按顺序返回预设的定稿句）测试整个流程。要验证：定稿句拼成整段后只整理一次，整理结果一次上屏；整理失败时上屏原文，并把原因告诉手机端；整理结果为空时不上屏；整理关闭时原样上屏；识别出错时已定稿的句子照常处理；取消和断线时什么都不上屏。
- 手机端用假的连接验证：取消时通知电脑端，之后不再提示这次语音输入的结果；电脑端告知整理失败时提示用户。
- 各识别服务的消息格式和定稿逻辑，按官方文档写单元测试。
- 设置的保存与读取用单元测试验证，包括密钥两端空白被去掉、空密钥被删除、设置文件只有当前用户可以读写、保存的模型不在列表里时改用默认模型、已去掉的预设能正常读取。
- 识别准确率和延迟用用户自己的真实语音实测，不放进自动化测试。

## Out of Scope

- 说话时在手机端显示识别中的文字。
- 整理结果边生成边上屏（ADR-0013）。
- 从服务商的接口获取模型列表（ADR-0007）。
- 上屏前先在手机端编辑语音文字：为了让语音和打字都直接上屏，已经去掉。
- 本地识别模型和本机的整理模型（保留为以后的选项，见 ADR-0005）。
- 用剪贴板粘贴上屏。
- 按当前应用调整语气、从用户的修改中自动学习词汇、选中文字后用语音指挥改写。
- 说完后改写语气和措辞。
- iOS 的录音（第一版只发布 Android）。

## Further Notes

- 待定：豆包 2.0 支持图片上下文，可以把当前窗口截图作为屏幕参考；但文档没写图片能不能直接放在请求里，要实测后再决定。
- 待定：部分终端、远程桌面、游戏不接受 Unicode 键盘事件，是否改用剪贴板粘贴，要实测后再定。
- 预设的模型列表会随各家更新而过时，要随应用更新。火山方舟的两个模型实测过整段整理的速度和效果；其他几家按官方文档确认模型名和关闭深度思考的写法，还没有实测。
- 实测：用合成语音加人为停顿，豆包在停顿约 1 秒以上时切句，半截话不带句尾标点；松开后识别收尾要 0.2–0.6 秒。整段整理用豆包 Seed 2.0 mini，158 字约 1 秒，448 字约 2.5 秒（ADR-0013）。
- 实测发现：豆包语音和火山方舟的密钥不通用，需要分别在两个控制台申请；火山方舟的模型要先在控制台开通才能调用，没开通时返回 `ModelNotOpen`。
- 声音和屏幕参考都会上传到所选的云服务，费用按各家计费。
