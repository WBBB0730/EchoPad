# dictation

**语音输入**

## Problem Statement

在电脑上打字慢。用户想用说话代替打字，并且要求识别尽可能准、说完马上出字，而且输入的文字是整理过的。现有的语音输入产品很难同时做到：边说边出字的产品基本照原话转写，口头禅和重复都会留下；整理得好的产品，说完要等 2–3 秒。

## Solution

按住手机端的说话按钮开始说话。识别过程中，临时文字显示在手机端。识别服务每给出一个定稿句，就立刻整理，整理好立即上屏到电脑的插入点。松开按钮后，只需要等最后一句整理完。说错的字用手机键盘上的退格修改（docs/prd/typing.md）。

EchoPad 不内置任何密钥（ADR-0007）。用户在电脑端的设置里选择识别服务和整理服务，填写自己的密钥；整理服务可以关闭。

## User Stories

1. 作为用户，我希望按住说话按钮就开始语音输入，松开就结束。
2. 作为用户，我希望说话时能在手机端看到临时文字，这样知道识别是否正常。
3. 作为用户，我希望只有整理好的文字才上屏，临时文字不会打进电脑。
4. 作为用户，我希望口头禅和重复自动去掉，标点也正确。
5. 作为用户，我希望句内改口时只保留我最后的说法。
6. 作为用户，我希望松开按钮后，最后一句几乎马上就上屏。
7. 作为用户，我希望当前窗口里出现的专有名词能被正确识别。
8. 作为用户，我希望上屏文字出现在电脑当前的插入点，中文能正常输入。
9. 作为用户，我希望说到一半断线时，未完成的内容不会上屏。
10. 作为用户，我希望电脑端没配置好或识别出错时，手机端能告诉我。
11. 作为用户，我希望在电脑端的设置里选择识别服务，填写自己的密钥。
12. 作为用户，我希望从几家预设中选择整理服务，也能填自己的服务地址和模型。
13. 作为用户，我希望不想付整理的费用时可以关闭整理，识别结果原样上屏。
14. 作为用户，我希望在设置里看到已保存的密钥，方便核对和复制，同时密钥默认遮住，不被旁人看到。

## Implementation Decisions

- 手机端按住说话期间录制 16kHz、16 位、单声道音频，每 100ms 发一段给电脑端（ADR-0005）。
- 识别服务（ADR-0005）：
  - 豆包流式语音识别（默认）：双向流式（优化版）接口，资源可选 2.0 或 1.0 的小时版、并发版，默认 2.0 小时版。开启二遍识别（每句话停顿约 0.8 秒后判定说完，用更准的非流式模型重新识别，结果才标记为定稿句）和语义顺滑（识别时就去掉语气词和重复）。附带屏幕参考。
  - 阿里百炼 Fun-ASR 实时识别：模型 `fun-asr-realtime`，句子停顿 0.8 秒判定说完；第一版不附带屏幕参考。
- 屏幕参考第一版只附带当前应用和窗口的名称，作为文字上下文。读取窗口标题用的是辅助功能权限，模拟键鼠本来就需要这个权限。
- 临时文字回传给手机端显示，不上屏。
- 每个定稿句立即交给整理服务整理，整理完立即上屏，上屏后不再修改（ADR-0006）：
  - 整理服务的预设：火山方舟（默认模型 `doubao-seed-2-1-lite-260915`）、阿里百炼（`qwen3.8-flash`）、DeepSeek（`deepseek-v4-flash`）、OpenAI（`gpt-5.4-mini`）、OpenRouter、本机 Ollama，以及自定义地址。有默认模型的预设同时关闭深度思考；其余由用户填写模型；
  - 本次语音输入里已整理的文字（最多 200 字）作为整理时的参考；
  - 整理失败或超过 8 秒时，使用识别原文，不丢掉用户说的话；
  - 整句都是口头禅时，整理结果为空，不上屏；
  - 英文句子之间自动补一个空格；
  - 整理关闭时，定稿句原样使用。
- 上屏用 Unicode 键盘事件直接输入。
- 设置（ADR-0007）：
  - 服务选择、模型、开关和密钥都保存在电脑端的设置文件里，文件只有当前用户可以读写；设置界面显示已保存的密钥，默认遮住，可以点开查看；清空输入框再保存即删除密钥；
  - 同一家服务商的密钥只填一次，例如识别和整理都选阿里百炼时共用一个密钥；
  - 保存后立即生效，不用重启电脑端；
  - 识别服务没有密钥，或整理开启但没配置好时，语音输入不可用，界面和手机端都会提示。

## Testing Decisions

- 只测外部行为：用假的识别服务（按顺序返回预设的临时文字和定稿句）测试整个流程。要验证：临时文字不上屏；定稿句按顺序整理后上屏；整理失败时使用原文；整理关闭时原样上屏；识别出错时已定稿的句子照常处理；断线时未完成的内容被丢弃。
- 各识别服务的消息格式和定稿逻辑，按官方文档写单元测试。
- 设置的保存与读取用单元测试验证，包括密钥两端空白被去掉、空密钥被删除、设置文件只有当前用户可以读写。
- 识别准确率和延迟用用户自己的真实语音实测，不放进自动化测试。

## Out of Scope

- 跨句改口的自动处理（可以用手机键盘退格后重说或重打）。
- 上屏前先在手机端编辑语音文字：为了让语音和打字都直接上屏，已经去掉。
- 本地识别模型（保留为以后的选项，见 ADR-0005）。
- 用剪贴板粘贴上屏。
- 按当前应用调整语气、从用户的修改中自动学习词汇、选中文字后用语音指挥改写。
- 说完后整段重写。
- iOS 的录音（第一版只发布 Android）。

## Further Notes

- 待定：豆包 2.0 支持图片上下文，可以把当前窗口截图作为屏幕参考；但文档没写图片能不能直接放在请求里，要实测后再决定。
- 待定：部分终端、远程桌面、游戏不接受 Unicode 键盘事件，是否改用剪贴板粘贴，要实测后再定。
- 预设的默认模型会随各家更新而过时，用户可以在设置里改。
- 实测发现：豆包语音和火山方舟的密钥不通用，需要分别在两个控制台申请。
- 声音和屏幕参考都会上传到所选的云服务，费用按各家计费。
