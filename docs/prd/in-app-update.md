# in-app-update

**应用内更新**

## Problem Statement

发版之后，用户还得自己去 GitHub 下载、重新安装，电脑端和手机端都一样。两端各自更新，就一定会碰上一端新、一端旧的时候。现在两端连接时不核对版本，旧的一端收到看不懂的消息只会默默忽略：用户只觉得某个功能没反应，也不知道该更新哪一端。

## Solution

两端都以公开仓库最新的 GitHub Release 作为唯一的更新源，在应用里检查、后台下载，用户确认后再安装。电脑端用 Tauri 官方的更新插件；手机端自己下载 APK，交给系统安装（ADR-0009）。确认之前，用户能看到当前版本之后每一版的更新日志。两端连接时核对协议版本：对不上就不连接，并明确告诉用户该更新哪一端（ADR-0010）。

## User Stories

1. 作为用户，我希望电脑端和手机端都能自动发现新版本，这样不用自己盯着发布页。
2. 作为用户，我希望启动之后过一小会儿再检查，之后每隔大约 4 小时再查一次，这样不和启动抢资源，当天晚些时候发的版本也能收到。
3. 作为用户，我希望能在设置里手动检查更新、看到当前的版本号，这样刚发版时能马上查。
4. 作为用户，我希望发现新版本后在后台下载，这样不打断我正在做的事。
5. 作为电脑端用户，我希望新版本下载好之后，首页状态列表里多出一行"新版本可用"和"更新"按钮，这样一眼就能看到。
6. 作为手机端用户，我希望新版本下载好之后，"设置"按钮上出现一个小圆点，这样不占用触控区也能注意到。
7. 作为用户，我希望更新提示不能关掉、也不能跳过，一直留到装上为止，这样不会忘了更新。
8. 作为用户，我希望点"更新"后先看到这次更新的日志，确认后才安装，这样心里有数。
9. 作为用户，我希望隔了好几个版本才更新时，日志里列出中间每一版的改动，这样不会漏看。
10. 作为电脑端用户，我希望确认之后电脑端自动重启并装上新版本，这样马上就能用。
11. 作为电脑端用户，我希望新版本已经下好时，从菜单栏退出也会顺手装上，下次打开就是新版本。
12. 作为电脑端用户，我希望更新之后辅助功能权限仍然有效，不用重新授权。
13. 作为用户，我希望电脑端重启更新期间，手机端会自动重连，不用重新配对。
14. 作为手机端用户，我希望第一次更新时被引导去允许"安装未知应用"，允许之后回到 EchoPad 就能继续更新。
15. 作为手机端用户，我希望更新之后配对仍然有效，打开就能自动连上电脑端。
16. 作为用户，我希望检查失败时当作已是最新、不显示错误，过一会儿自动重试，这样网络波动或正在发版时不会被打扰。
17. 作为用户，我希望下载失败时能在设置里看到提示并重试。
18. 作为用户，我希望两端版本不兼容时，两端都明确提示该更新哪一端，而不是功能默默失效。
19. 作为用户，我希望版本不兼容时配对仍然保留，更新完较旧的一端就自动连上，不用重新扫码。
20. 作为开发者，我希望开发版也会检查更新、显示同样的提示和更新日志，但确认后打开该版本的 Release 页面，而不是在开发版上安装，这样能在本地检查更新界面。

## Implementation Decisions

- **更新源（ADR-0009）**：公开仓库的 `releases/latest/download/latest.json`，由发版流程生成（见 `docs/prd/release.md`）。只认最新的正式 Release；清单里的版本比当前版本新，才算有更新。
- **电脑端**：用 `tauri-plugin-updater` 检查、校验签名和安装。公钥写在 `tauri.conf.json` 里，更新包必须用对应的私钥签名，否则拒绝安装。下载和安装分两步：发现新版本就先下载，用户确认或退出时再安装，装完重启。更新的整个流程放在 Rust 侧，和现有的状态一样，通过事件推给界面。
- **手机端**：读同一份 `latest.json` 里的版本号和更新日志；APK 的下载地址按版本号拼出，Release 上的 APK 名字是固定格式。用现有的 Ktor 客户端下载，存到应用的缓存目录，再用系统的 `PackageInstaller` 会话安装。清单文件声明 `REQUEST_INSTALL_PACKAGES`；用户还没允许"安装未知应用"时，先打开系统里对应的设置页，回来后继续。Android 12 及以上，满足条件时自己更新自己不再弹系统确认，但仍要处理"需要用户确认"的情况。安装时系统会核对新 APK 和已装版本的签名，不一致直接拒绝，所以 APK 不再另外校验签名。更新的流程放在共享代码里，下载后的安装放在 `androidMain`。
- **检查节奏**：启动后稍等一个短的随机时间再检查，运行期间大约每 4 小时一次；打开设置（电脑端的设置页、手机端的设置面板）时，距离上次检查超过 5 分钟就再查一次；手动检查不受这个限制。手机端只在 App 处于前台时检查，回到前台时如果距离上次已超过 4 小时，也会检查。检查失败时显示为已是最新、不报错，大约 15 分钟后静默重试；已经有可用更新时，再次检查的结果不会把它撤回。下载失败时在设置里提示，可以重试。
- **更新提示**：两端的提示都不能关闭，也不能跳过。
  - 电脑端：新版本下载好后，首页状态列表里多一行，写法和其他状态行一样：圆点 + "新版本 X 可用"，右侧是"更新"按钮。设置页的卡片最后加一张"关于"卡片：版本号，以及"检查更新"或"立即更新"按钮。
  - 手机端：新版本下载好后，触控板页的"设置"按钮上出现一个小圆点。设置面板最下面加一行：版本号，右侧是"检查更新"或"立即更新"按钮。
  - 设置里的按钮只有两种文字：已经有可以安装的更新时写"立即更新"，其他时候写"检查更新"；正在检查或下载时只把按钮置灰，不换文字（同 DevCube）。
- **更新弹窗**：电脑端是对话框，手机端从底部弹出。标题"EchoPad X 可用"，副标题"当前版本 Y"；下面从新到旧列出当前版本之后、到新版本为止每一版的更新日志，一段都没有时写"无更新日志"。日志正文按 Markdown 显示（列表、加粗、链接），链接在系统浏览器里打开。按钮是"取消"和主按钮：电脑端写"重启并更新"，手机端写"更新"，开发版写"前往下载"。设置里的"立即更新"和首页的"更新"打开的是同一个弹窗。
- **安装**：电脑端确认后安装并重启；从菜单栏"退出"时，如果新版本已经下好，先装好再退出。手机端确认后交给系统安装，App 会被系统关闭，用户重新打开时就是新版本。
- **开发版（同 DevCube ADR-0017）**：电脑端的 `tauri dev` 和手机端的 debug 构建照常检查、显示提示，但不在后台下载；确认后打开该版本的 GitHub Release 页面。debug 构建的签名和发版签名不同，本来也装不上发版的 APK。
- **版本核对（ADR-0010）**：`echopad.proto` 定义一个整数协议版本，两端从同一处取值。手机端在 `Hello` 里带上自己的协议版本；电脑端先核对版本、再验证配对，版本不一致时回 `Rejected`，原因写版本不兼容，并带上电脑端自己的协议版本，这时不消耗配对口令。协议版本只在一端需要理解另一端的新内容时加一，比如新增或删除消息、字段，或者改变了含义。两端都提示更新协议版本较小的那一端：
  - 手机端：保留配对，按原来的间隔继续重连；连接状态那一行写"手机端需要更新"或"电脑端需要更新"。
  - 电脑端：首页"手机端连接"那一行写"手机端需要更新"或"电脑端需要更新"。
  - 只有版本不兼容时才保留配对；其他原因的拒绝照旧清除配对、回到配对页（见 `docs/prd/pairing.md`）。
- **模块划分**：两端各有一组更新策略的纯函数，输入当前版本和清单，算出有没有更新、要列出哪几段日志、提示怎么显示、点了按钮做什么。电脑端的更新流程（检查、下载、安装、重启、退出时安装）在 Rust 侧；手机端的在共享代码里。版本核对放在两端现有的连接代码里。

## Testing Decisions

- 只测外部行为，不测真实的 GitHub 网络，也不测真实安装。
- 更新策略：版本比较；挑日志段（区间的上下界、没写的版本跳过、从新到旧）；开发版点击后的动作；已有可用更新时再次检查不会撤回；检查失败当作已是最新并安排重试（用模拟时间）。
- 版本核对：电脑端用集成测试模拟手机端连接，测版本不一致时回版本不兼容、不消耗配对口令，版本一致时照常配对。手机端用假连接测试，测收到版本不兼容时保留配对、继续重连，并提示该更新哪一端；收到配对失效时照旧清除配对。
- 维护者冒烟：真实的检查、下载、安装和重启，只能在正式签名的包上验证。先装旧版本，发新版本后确认两端都能更新，并且电脑端的辅助功能权限仍然有效、手机端的配对仍在。

## Out of Scope

- Beta 线（见 `docs/prd/release.md`）。
- 跳过某个版本、暂时隐藏更新提示。
- 除了版本不兼容以外的强制更新。
- 手机端在后台检查或下载；更新完自动重新打开 App。
- 电脑端在局域网里把 APK 分发给手机端。
- 开发版的更新日志本地预览按钮（DevCube 有这个功能）。
- 差分更新。

## Further Notes

- 电脑端的 Tauri 更新签名私钥和手机端的发版签名文件，是应用内更新能接得上的前提。丢了或换了，已安装的用户只能手动重装，手机端重装还会丢掉配对。
- macOS 按签名识别 App，电脑端更新之后签名不变，辅助功能授权才会保留。
- 国内访问 GitHub 可能很慢或者失败，表现为检查失败（当作已是最新）或下载失败（在设置里提示）。如果这成了主要问题，可以重新考虑由电脑端分发手机端的安装包。
- 以后如果上架 Google Play，要去掉 `REQUEST_INSTALL_PACKAGES`，改由商店负责更新。
- 实现之后，把新增的界面写进 `DESIGN.md`，把发版步骤和需要准备的凭证写进 `README.md`。
